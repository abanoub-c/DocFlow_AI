# DocFlow AI - Synthetic Benchmark Dataset

75 fictional documents with exact ground truth: **60 invoices** and **15 receipts**.
Generated by `evals/generator/generate_dataset.py` (seed `42`, generator v1.0).
All companies, addresses, phone numbers and e-mail addresses are invented (e-mails use the reserved `.example` domain).
Every page carries a small "synthetic sample" footer.

## Mix

| | Invoices (60) | Receipts (15) |
|---|---|---|
| Language | ar: 20, bilingual: 10, en: 30 | ar: 5, bilingual: 2, en: 8 |
| Quality | clean_scan: 15, degraded: 15, digital: 30 | clean_scan: 4, degraded: 8, digital: 3 |
| Layout | boxed: 15, classic: 14, minimal: 15, modern: 16 | store: 8, thermal: 7 |

* `digital`: PDF with a text layer. `clean_scan`: flat scan (PNG or image-only PDF, no text layer).
  `degraded`: JPG with rotation, perspective, blur, noise, uneven light and compression
  (receipts are photo-style: desk background, shadow, paper curl).
* Arabic invoices use Arabic-Indic digits (٠١٢٣) in about half of the documents.
* Bilingual invoices print labels in both languages; the vendor is English, the customer Arabic, line items mixed.

## Files

```
evals/dataset/
  documents/        the 75 input files (pdf / png / jpg)
  ground_truth/     one JSON per document
  manifest.csv      one row per document (type, file, language, quality, layout, edge case, expected issues)
```

## Ground-truth rules (the scorer must follow these)

1. **Printed values.** Ground truth is what is printed, including wrong totals in edge cases.
2. **`null`** means the field is not printed on the document.
3. **Digits** are ASCII in ground truth. Normalise Arabic-Indic digits (and `٫` `٬` `٪`) in predictions before comparing.
4. **Dates** are ISO-8601 (`2026-03-14`). **Times** are 24h `HH:MM`.
5. **Money and quantities** are JSON numbers; **tax rates** are fractions (`0.14`).
6. **Text fields** (names, addresses, descriptions, payment terms) keep the printed wording; compare with normalised whitespace (and a fuzzy threshold if you like).
7. **`payment_method`** is a normalised enum: `cash`, `card`, `mobile_wallet`.
8. **`discount`** is `null` when no discount line is printed (treat as 0 in arithmetic).

## Fields

**Invoice (`invoice_v1`)**: vendor_name, customer_name, customer_address, invoice_number, invoice_date, due_date, currency,
subtotal, tax_total, discount, total_amount, payment_terms, language, line_items[description, quantity, unit_price, tax_rate, line_total].

**Receipt (`receipt_v1`)**: merchant_name, merchant_address, receipt_number, date, time, payment_method, currency,
subtotal, tax, total, language, items[name, quantity, unit_price, line_total].

Extra printed text (vendor address, phone, e-mail, tax registration number) appears on many invoices as realistic distractors; it is not part of the schema.

## Edge cases

| Document | Type | Edge case | Language / quality | Expected validation issues |
|---|---|---|---|---|
| `inv_002` | invoice | line_total_mismatch | en / degraded | line_total_mismatch |
| `inv_015` | invoice | missing_due_date | ar / digital | missing_field:due_date |
| `inv_019` | invoice | tax_mismatch | bilingual / digital | tax_mismatch |
| `inv_026` | invoice | duplicate_copy | en / degraded | duplicate_document |
| `inv_027` | invoice | total_mismatch | en / digital | total_mismatch |
| `inv_055` | invoice | missing_invoice_number | en / clean_scan | missing_field:invoice_number |
| `inv_058` | invoice | duplicate_original | en / digital | (none: this is the original of a duplicate pair) |
| `inv_060` | invoice | total_mismatch | ar / clean_scan | total_mismatch |
| `rcp_009` | receipt | cash_rounding | en / degraded | (none: validator must tolerate it) |

`meta.expected_issues` is computed by the generator's own validator, so it always matches the arithmetic of the ground truth.
`meta.expected_review` is `true` when at least one issue is expected (the document should go to human review).
Issue codes: `total_mismatch`, `line_total_mismatch`, `tax_mismatch`, `subtotal_mismatch`, `missing_field:<name>`, `duplicate_document`.

## Reproduce

```bash
pip install -r evals/generator/requirements.txt
playwright install chromium          # also needs poppler (pdf2image) and Arabic fonts (Noto Naskh/Sans Arabic, Amiri)
python evals/generator/generate_dataset.py --seed 42
```

Fonts used (all open source): Inter, Carlito, Caladea, DejaVu, Noto Sans/Naskh/Kufi Arabic, Amiri.

## Honest limits

* Synthetic documents are cleaner and more regular than real supplier invoices. Report results on this set separately from results on public datasets (DocILE, CORD, CORU, ...).
* Arabic text layers in the digital PDFs are imperfect, as in many real PDFs (for example the lam-alef ligature can be extracted in swapped order). This is deliberate realism: compare text-layer extraction with OCR on the Arabic documents.
* Only English, Arabic and bilingual layouts from four invoice and two receipt templates; no handwriting, stamps or multi-page documents.
